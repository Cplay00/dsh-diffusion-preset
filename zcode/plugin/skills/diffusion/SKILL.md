# 扩散模式 · ZCode 原生兼容版

以当前请求实际暴露的工具及宿主目录为准。已有工具直接用，已知名称精确加载，未知能力再检索；只加载任务需要的工具。用户和工作区规则、技能要求以及 ZCode 权限始终有效。

## 发现与调用

1. 查看当前请求中的常驻工具及 ZCode 提供的延迟工具名称公告。名称可用于浏览，不能据此猜参数。当前目录没有的能力不宣称已安装。
2. 存在 `ToolSearch` 时，使用原生模式。已知名称传 `{"query":"select:<精确名称>","max_results":1}`；未知能力传简短关键词，通常取 1–5 个候选。返回完整定义后，在下一次工具调用中直接执行目标工具。
3. 存在 `LocalToolSearch` 时，使用本地模式。用同样的查询语法加载定义，再通过 `DeferredToolCall({"name":"<精确名称>","input":{...}})` 执行延迟工具。`input` 严格遵循返回的目标 Schema。常驻工具仍直接调用。
4. 两种搜索控件都没有时，使用已有工具正常处理任务；需要按需加载时，说明可在 ZCode 设置中启用 ToolSearch。插件提示词本身不会启用该功能。

优先遵循当前宿主工具的实际说明。工具名区分大小写；MCP 使用目录提供的完整名称。ZCode 关键词检索不支持正则，也不会自动复用 DSH 的中文同义词表；中文请求可结合目标能力转成简短英文关键词，例如文件搜索 `file search`、文档 `document docx`、表格 `spreadsheet excel`、网页提取 `web extract`。不要一次检索或加载全部工具。

搜索本身会加载匹配定义，不是 DSH 的只读 `lookup`。只想浏览时，根据当前延迟工具名称公告与已公开描述列出候选，标清没有描述的条目；需要取得完整定义时再搜索。搜索不执行目标操作，不要将搜索结果当作业务执行结果。已加载且仍在上下文中的定义可复用，不必反复搜索。

## DSH 操作对应关系

| DSH 操作 | ZCode 原生兼容行为 |
| --- | --- |
| `catalog` / 只读 `lookup` | 浏览当前常驻与延迟工具名称、技能元数据；不调用搜索控件，不假装得到完整 Schema |
| `detail` / `names` | 当前搜索控件的 `select:<精确名称>`；之后按 native/local 协议执行 |
| `query` | 将需求转换成宿主支持的关键词；搜索同时加载匹配定义 |
| `category` | 按名称、公开描述给出导航建议；ZCode 没有 DSH 分类挂载 API |
| `skill:<名称>` | 使用 ZCode 实际提供的技能加载方式；只在需要时读取技能正文 |
| `unload` / `reset` | 此兼容版不支持。不要写入伪造的挂载状态。新建会话可从宿主初始集合开始 |
| PTC / `run_code` | 此兼容版不提供；`DeferredToolCall` 是单工具调度入口，不是 PTC 沙盒 |

`/call-directory` 是目录辅助斜杠命令，不是原生 `call_directory` 工具。本插件没有替代权限门禁，也不改变宿主决定的常驻工具集合。
